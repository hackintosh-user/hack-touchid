Guide

Everything you need to build, run and use HTID.

Requirements

  • macOS 14 Sonoma or later (macOS 15 Sequoia or later recommended). Older versions get zero support.
  • OpenCore v1.0.6 or later. v1.0.5 and older are not supported.
  • Xcode Command Line Tools: xcode-select --install
  • Homebrew, then brew install libusb openssl@3 innoextract
  • Accessibility permission for the daemon. The deploy step handles this for you.
  • Your sensor must be enabled in your USBMap so it is powered. Check System Information, USB, for your sensor's VID:PID.

Heads up: openssl@3 is scheduled to be deprecated on November 1st 2026, but it should keep working.

1. Build

git clone https://github.com/hackintosh-user/hack-touchid.git
cd hack-touchid
chmod +x prep_and_build.sh
./prep_and_build.sh

This produces the client and each sensor's daemon and support files.

2. Run the client

sudo ./hack-touchid

On launch the client runs its startup checks, then clears the screen and draws the menu. If a check prints a warning or an error, the screen is not cleared so you can read it. The HTID logo, with the version, build and branch next to it, stays at the top of every screen, including after an action and in Settings. Use --q or --quiet for the plain startup (banner first, no clearing). After the first launch the client adds itself to your $PATH, so from any new terminal you can just run:

sudo hack-touchid

3. Use the menu

The menu has three parts: the logo and version line, a Status checklist, and the actions in two columns. Pick an action by typing its key at the Choice: prompt. In a plain terminal, or when the output is piped, the dots and lines fall back to ASCII.

Choice:

Status. A green dot means the item is ready, a yellow dot means it needs attention, and a dim dot means unknown. The Password and Fingers rows are not live checks: they fill in after you run Enroll, Verify or Deploy once in the session.

Sensor tools depend on the sensor that was detected:

  • Validity VFS5011 and UPEK: [C] View Fingerprint (capture preview, nothing saved) and [T] Sensor Test. UPEK also gets [U] Test Capture, which saves a .pgm image.
  • Metallica MIS and Prometheus 97: [P] Pair Sensor, [B] Calibrate Sensor and [N] Rename a Print. All three are marked experimental. Pairing normally happens by itself inside Enroll.
  • No sensor found: the column shows No sensor tools.
  1. Enroll a finger [1]. Captures several swipes and stores them as a named template on the encrypted volume. Repeat for as many fingers as you like. Verification uses best match wins.
  2. Verify [2]. A standalone test of capture and matching, independent of the daemon. The score is shown against your match threshold (the score/20 note). Use it to confirm everything works before deploying.
  3. Deploy [3]. Rebuilds the daemon, installs it as a per-user LaunchAgent, re-signs it, regenerates its Accessibility grant, and installs a narrowly scoped sudoers rule so it can reach the USB device. Re-run on every deploy so the daemon is never stale.

Once deployed, the daemon runs in the background. At the lock screen or a System Settings authentication sheet it asks for your fingerprint and, on a match, types the stored password. [FP] Fpbootd Pre-Login is a placeholder that does nothing yet, see Fpbootd.

[B] Back
  • Switch Branch [7]. The branch list is fetched live from GitHub. If GitHub cannot be reached it falls back to main and active-development. A branch is only saved if its VERSION.txt can be read, and the client then offers to install it. After an update installs, the branch it came from is pinned in VERSION.txt, so the next update check follows the same branch.
  • Show Recent Commits [CM]. Uses the same branch picker and prints the last 5 commits on the branch you choose.
  • Match Threshold, Swipe to Lock Sensitivity and the Sensor LED group are for VFS5011. The LED group only appears when a VFS5011 is detected.

Sensor guides

Pick your sensor, open its guide and follow it from top to bottom. You can find your sensor's VID:PID in System Information, USB. Steps marked (automatic) happen on their own; they are listed so you know what the client is doing. Every guide ends the same way: deploy the daemon, then optionally install the menu bar app and the Settings pane.

Validity VFS5011 138a:0018 Working

A swipe sensor. The client captures swipes and matches them on the Mac with NBIS, and your templates live on an encrypted volume.

  1. Build and start. Run ./prep_and_build.sh, then sudo hack-touchid. The banner should name your sensor. If no sensor is found, make sure it is enabled in your USBMap and visible in System Information, USB.
  2. Check the sensor with [C]. View Fingerprint shows a live capture preview and saves nothing. Swipe at a steady speed. If the image is faint, clean the sensor and your finger.
  3. Enroll with [1]. The first time, the client sets up the encrypted template volume and asks for your macOS login password. It has to be your real password, because it is what gets typed when your finger matches. Then name the finger (for example Right Index) and swipe until the bar is full (5 good swipes). Run [1] again for more fingers.
  4. Verify with [2]. Swipe once. The client shows your match score against the threshold (default 20). If real swipes score low, enroll again with a slower, steadier swipe, or lower the Match threshold in the Settings pane (lower accepts more swipes).
  5. Deploy with [3]. Installs the background daemon, signs it, regenerates its Accessibility permission and adds the scoped sudoers rule for USB access. Run it again after every update.
  6. Test it. Lock the screen with Ctrl+Cmd+Q and swipe at the lock screen, or open a System Settings padlock.
  7. Optional. [M] installs the menu bar app and [I] the Settings pane. On macOS 26 Tahoe the menu bar app also offers Swipe to Lock.
Synaptics Metallica MIS and Prometheus 06cb:009a 138a:0097 Working

Touch sensors that match on the chip. Your prints are stored on the sensor itself, and nothing about them is saved on the Mac. The sensor has to be paired to this Mac before it works, and the client does that for you.

  1. Install the dependencies and start. brew install libusb openssl@3 innoextract (MacPorts: libusb openssl3 innoextract 7zip). innoextract unpacks the firmware installer. Build, run sudo hack-touchid and check that the banner shows your sensor.
  2. Start with Enroll [1]. Everything below happens inside this one command, so just follow the prompts and choose or name the finger when asked.
  3. Pairing (automatic). A sensor nobody has paired yet gets a one-time setup: HTID writes the sensor's identity partitions and uploads its firmware, which it downloads from Lenovo and unpacks. The sensor restarts, the client waits about 8 seconds and carries on. Pairing swaps the sensor's trusted host identity, so fingerprints enrolled under Windows Hello or another OS on this sensor become unreadable there (they are orphaned, not deleted). [P] Pair runs this step by hand and asks you to type PAIR; you normally do not need it.
  4. Host identity (only if another OS paired the sensor first). The sensor derives its key from the laptop's real product name and serial number, and macOS only sees the spoofed Mac values. The client asks for both once. On Windows, in PowerShell: Get-CimInstance Win32_ComputerSystemProduct | Select Name,IdentifyingNumber. On Linux: cat /sys/class/dmi/id/product_name /sys/class/dmi/id/product_serial. They are saved for root only, so you are asked once. You can also pass them as --host-product and --host-serial.
  5. Secure session, TLS (automatic). The client opens an encrypted session with the sensor using the paired identity. If you see "The sensor rejected the secure connection", wait about 10 seconds and try again. If it keeps happening, attach /var/log/htid-metallica-enroll.log to a GitHub issue.
  6. Calibration (automatic, step 1 of 3). Keep your finger off the sensor until it says so. You can run it again any time from the Sensor tab of the Settings pane (or --mmis-calibrate).
  7. Enroll (steps 2 and 3). Touch the sensor with the same finger when asked. It usually needs about 10 good touches, then it saves the print on the sensor. If the sensor already holds prints, the client asks whether to replace them.
  8. Verify with [2], deploy with [3]. Verify with one touch, then Deploy to install the daemon. Run Deploy again after every update. On macOS 26 Tahoe, Touch to Lock is available in the menu bar app.

Starting over: --wipe-records deletes every print stored on the sensor and cannot be undone. [D] Diagnose creates a report for troubleshooting. The related ID 138a:009d is detected, but not working yet.

UPEK/AuthenTec TouchStrip 147e:2016 Experimental

Capture test only for now. Enroll, Verify and Deploy are not available for this sensor yet.

  1. Build and start. Run ./prep_and_build.sh, then sudo hack-touchid. The banner should name the UPEK TouchStrip.
  2. Capture with [U]. Swipe your finger and the client saves a .pgm image.
  3. Help the project. Generate a report with [D] Diagnose and attach it, with your .pgm images, to a GitHub issue. That is what moves this sensor forward.

Other sensors. Synaptics VFS7552 (138a:0092) is detected but has no working backend yet. To request a sensor, open a GitHub issue with its VID:PID and a [D] Diagnose report.

Menu bar app (optional)

The daemon works the same with or without it. It needs macOS 14 Sonoma or later.

Download the pre-compiled app from the Releases page, or build it:

cd Hackintosh-TouchID-Menubar
chmod +x build_menubar_app.sh
./build_menubar_app.sh
open "build/Hackintosh Touch-ID.app"
  • First launch is blocked by Gatekeeper because the app is ad-hoc signed. Right-click, Open, Open again, or run xattr -cr "Hackintosh Touch-ID.app".
  • The daemon needs a small patch to send events to the app. See the daemon patch README.
  • While a prompt (padlock, Passwords, Keychain Access) needs your finger, a card appears at the top middle of the screen, above all apps. It needs no notification permission. Run HackintoshTouchID --overlay-demo to preview every card.
  • The card also shows on the lock screen. The app moves it into a private SkyLight space above the login window, using the technique of the MIT licensed SkyLightWindow package. To turn the lock screen card off, run defaults write com.vfs5011.hackintosh.menubar OverlayOnLockScreen -bool NO. If the SkyLight symbols are missing, the app falls back to Notification Center banners; for readable banners, set System Settings, Notifications, Show Previews to Always.
  • Pause and resume is global, it affects every recognized prompt at once.
  • If the card is blocked or missing, the Notification Center banners fallback is cleared automatically after each attempt, so they do not pile up.

Swipe to Lock (macOS Tahoe only)

macOS 26 Tahoe only, and VFS5011 sensors only. The menu item does not appear on earlier macOS versions, and the daemon ignores the setting there.

  • Choose Enable Swipe to Lock in the menu bar app. The sensor lights up, and one swipe locks the screen (Ctrl+Cmd+Q). Choose Disable Swipe to Lock to turn it off.
  • It never matches a finger or types a password for the lock. It steps aside for the real lock screen and padlock prompts, then arms again.
  • The setting is remembered across daemon restarts and reboots. Update the daemon together with the app.
  • The daemon needs Accessibility access to send the lock keystroke.
  • The sensor stays lit while it is on. The client's Enroll and Verify cannot open the sensor meanwhile, so turn Swipe to Lock off first.
  • It detects that a swipe happened, not its direction.

Fpbootd: pre-login authentication

Fpbootd is an experimental effort to use your fingerprint before you have logged in to macOS. Today HTID only works after login, at the lock screen and in authentication prompts.

Not usable yet. This is early research, with no release date.

Current state

  • Early spike code is committed on the active-development branch.
  • The [FP] entry in the client menu is a placeholder. It does nothing yet.
  • Cold boot sign-in is not supported. See Limitations.

Progress is announced in the changelog.

How it works

Capture

The raw USB protocol is implemented directly against libusb with no Linux driver stack.

Matching

NIST's mindtct extracts minutiae and bozorth3 scores matches, both compiled in.

Storage

Templates and the password sit on an encrypted APFS volume. Its passphrase is in the System keychain.

Detection

The daemon watches the focused UI element through the Accessibility APIs. It patches no system process.

Privilege model

Runs as the console user and only escalates to root, via a scoped sudoers rule, for USB access. Not a system LaunchDaemon.

Limitations

  • macOS only, and only macOS 14 Sonoma or later. On Linux, use the libfprint driver directly.
  • Swipe to Lock works only on macOS 26 Tahoe with a VFS5011 sensor. Touch to Lock works only on macOS 26 Tahoe with a Metallica MIS sensor.
  • No PAM module for sudo in a terminal yet. It is planned, but it is unknown whether modern macOS allows it.
  • Ad-hoc code signing only. No notarization or Developer ID.
  • Cold boot sign-in is not supported. macOS does not allow this level of access at the login window before a user has logged in. It could take months or years.
